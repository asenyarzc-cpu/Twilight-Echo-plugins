# 酷狗音乐音源

Twilight Echo 的酷狗音乐 Provider 插件。

- 插件 ID：com.twilightecho.provider.kugou
- Provider ID：kugou
- 当前版本：0.2.3

## 前置条件

无。KuGouMusicApi 兼容服务（MakcRe/KuGouMusicApi，MIT）已作为自包含 bundle 内嵌在插件中（`vendor/kugouApi.vendor.cjs`），并固定使用与登录、播放接口相匹配的概念版（lite）平台配置，随插件宿主进程启动：

- 首次请求时懒启动，仅监听 `127.0.0.1` 的随机端口，不与其他程序抢端口；
- 设备标识（GUID/DEV/MAC）首次生成后持久化在插件私有设置中，跨重启稳定；
- 应用退出或禁用插件时服务随之关闭。

高级用户可在插件设置中改为连接本机已部署的 KuGouMusicApi 地址（仅允许 localhost、127.0.0.1 或 ::1）；留空则始终使用内置服务。不支持公共 API、Vercel 部署或第三方代理。插件会将旧版本遗留的默认 `http://127.0.0.1:3000` 配置自动迁移为内嵌服务，避免误连本机的其他音源 API。

启动后，在 Twilight Echo 的 设置 → 插件设置 → 酷狗音乐音源 中阅读免责声明并确认。首次请求会向酷狗注册一个插件专用的匿名设备标识；不会读取真实硬件标识。

## 功能

- 搜索歌曲、歌手和公开歌单
- 本机 Range 音频代理，支持 seek 和短期播放 URL 刷新
- 歌词搜索、普通歌词与 KRC 逐字歌词
- 酷狗二维码登录、用户资料与用户歌单
- 播放质量按 无损、320、128 自动降级

歌曲、歌单和歌手搜索使用酷狗公开搜索接口，不依赖账号登录；个人资料、用户歌单和播放地址仍需扫码登录。0.2.2 将二维码登录和播放统一迁移到概念版（lite）平台，并在扫码完成后立即验证账号，避免无效凭据被误报为“登录成功”。0.2.3 修复认证 Cookie 中分号后的空格导致上游解析器丢失 `token`、`userid` 和 `dfid`、进而把正常登录态误报为 20028 的问题；同时停止把插件回环地址伪装成上游客户端 IP，并避免把 `free_part=false` 字符串误判为试听请求。旧版本保存的普通版登录态不能跨平台复用，升级后需要重新扫码一次。

播放请求会携带搜索结果中的专辑 ID 和专辑音频 ID，并按 无损、320、128 自动降级。若账号、地区、会员或版权权限不允许播放，插件会返回上游错误，不会绕过访问限制。

插件只提供只读的 Provider 能力。不提供下载、写入歌单、收藏写入、听歌历史上报、VIP 绕过或访问限制绕过。

## 使用

1. 安装插件并确认免责声明（服务自动随应用启动，无需任何外部部署）。
2. 在流媒体页直接搜索歌曲、歌手或歌单；播放及访问个人歌单前，在登录页重新扫码一次。

退出登录会清除插件私有认证数据和内存中的播放令牌。插件不会把 token、userid、dfid、Cookie 或二维码会话写进曲目字段、错误信息或日志。

## 重新构建内嵌服务

```shell
# 上游克隆默认位于 D:\KuGouMusicApi，可用 KUGOU_API_SRC 覆盖
pnpm run build:kugou-vendor
pnpm test
```

构建脚本会校验上游 commit 与 `scripts/build-kugou-vendor.mjs` 中的 pin 一致；升级上游时先审核 diff，再更新 pin 并重新构建。详见 `vendor/VENDOR.md`。
